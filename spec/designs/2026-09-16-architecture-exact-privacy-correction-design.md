# Точное исключение для обезличивания замороженного документа

## Граница

Разрешённое обезличивание существующего документа не меняет его архитектурный
смысл, но отличается побайтово от опубликованной базы. Обычная проверка
заморозки поэтому блокирует следующую публикацию. Согласование вне CI не
является автоматически проверяемым условием.

Добавляется ровно один направленный переход содержимого, а не общий режим
редактирования frozen documents. Требование неизменяемости сохраняется для
всех остальных пар содержимого, включая дальнейшие изменения этого же файла.
Правило процесса фиксируется в candidate process v3 до его принятия.
Это процессная коррекция; product ADR, invariant и contract для неё не создаются.

## Требования

### FROZEN_PRIVACY_CORRECTION_IS_CONTENT_BOUND

Проверка `FROZEN_DOCUMENT_MODIFIED` допускает только одновременное совпадение:

| Поле | Единственное допустимое значение |
| --- | --- |
| Путь | `spec/plans/2026-07-22-unified-diagnostic-chips-plan.md` |
| SHA-256 исходных полных bytes | `7d80ad64850c9e1f27590d4bc87e7870b9240c7d3d180345ddf57832cf9ca235` |
| SHA-256 исправленных полных bytes | `ee7d23440d858552f2bd1bc0ca77b555c959b6b77445c7d9fe64e6aa2cb0059b` |

Оригинальные частные значения, их фрагменты и преобразующий patch в репозиторий
не возвращаются. Здесь хранится идентичность проверенного перехода, не исходный
текст. Front matter и содержательные обязательства при этом переходе прежние.

Проверка выполняется после проверки identity и пути: deletion/move нельзя
оправдать совпадением checksum. Не меняются проверки schema, графа, plan
completion, fitness и самого process document. Равные bytes идут по обычному
пути без исключения; обратный переход, дополнительные bytes, иной документ
и другой исходный текст отвергаются. Повторная проверка той же пары допустима:
«однократный» означает единственный переход, не одно выполнение CI job.

Никакие CLI flags, environment variables, user-controlled manifests или
перечни путей из PR не включают обход. Единственная пара зафиксирована в коде;
её расширение само требует нового рассмотренного процессного решения.
Изменение опубликованной истории, push, настройки GitHub и права эксплуатации
этот механизм не разрешает. После принятия обезличенный текст становится
обычной замороженной базой.

## Реализация и приёмка

В отдельном `scripts/v8std_architecture_privacy.py` находится неизменяемая
декларация пары и чистая функция `is_exact_privacy_correction(path, before,
after) -> bool`. `validate_frozen_documents` вызывает её только в ветке
изменённого содержимого. Чтение произвольного внешнего файла или исполнение
деклараций отсутствует.

Новый `tests/test_v8std_architecture_privacy.py` проверяет helper на синтетическом
тексте, отрицательные варианты и соответствие реального исправленного файла
закреплённой checksum. Синтетические тесты подменяют только внутреннюю пару,
не вводят runtime/test override в CLI. Старые freeze tests остаются обязательными.

Отдельная интеграционная команда сравнивает checkout с реальной опубликованной
базой. Она должна перестать выдавать именно эту ошибку; чужие frozen edits
по-прежнему обязаны давать ошибку. Этим не доказываются готовность clean-host
runtime, внешняя публикация или удаление старых данных с GitHub.

## Альтернативы

- Исключение только по имени файла повторно разрешало бы любую его правку.
- Флаг отключения freeze расширял бы полномочия на весь корпус документов.
- Переписывание опубликованной истории относится к другой внешней операции
  и не является условием этой исправляющей поставки.
- Преемник без изменения прежнего файла сохранил бы частный текст в текущем
  дереве и не выполнил бы задачу обезличивания.

Выбран точный переход: сохраняет проверку всех остальных изменений и не
восстанавливает частные значения в публичном репозитории.
